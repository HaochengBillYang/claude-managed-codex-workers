# Troubleshooting

| Symptom | Cause | Fix | Source |
| --- | --- | --- | --- |
| `Computer Use was not approved to use <App>` in a headless run | The app is missing from Codex's persistent Always-allowed list. One-time approvals do not carry over to headless runs, including forks of the approved thread. | In the Codex app, have the user enter `@Computer open <App>` and choose **Always allow**, then rerun. On a new Mac, grant Accessibility and Screen Recording to **Codex Computer Use**. | [Setup · GUI / computer use](../setup.md#gui--computer-use-verified-2026-11-21), [Setup · New machine](../setup.md#new-machine), [Skill · Pick sandbox](../skills/codex/SKILL.md#3-pick-sandbox) |
| Chrome reports `Ambiguous app identifier` | A mounted Chrome installer DMG makes the bundle ID ambiguous. | Use the full installed app path in the brief with `cua.getApp("/Applications/Google Chrome.app")`. | [Skill · Pick sandbox](../skills/codex/SKILL.md#3-pick-sandbox) |
| `The browser access host is unavailable` | Browser Use needs the Codex app's bridge, which is unavailable in headless runs. | Brief the worker to drive Chrome as a native app using `cua.getApp("/Applications/Google Chrome.app")` and keystrokes. Chrome needs its own Computer Use approval. | [Skill · Pick sandbox](../skills/codex/SKILL.md#3-pick-sandbox) |
| The band shows **update ready** | A newer plugin version is installed while the open session is still running the previous version. | Run `/reload-plugins` in the open Claude Code session. | [Skill · Land without outages](../skills/codex/SKILL.md#7-land-without-outages), [Design · v0.2.5 drift notice](codex-workers-design.md#v025-drift-notice) |
| `STATUS=OK` | No budget restriction applies. | Delegate normally. Queue drain defaults to up to four concurrent workers. | [Skill · Check budget first](../skills/codex/SKILL.md#1-check-budget-first-every-time), [Design · Contract D](codex-workers-design.md#contract-d-queue) |
| `STATUS=THROTTLE` | The 5-hour window is at least 70% used, or weekly usage is more than 15 percentage points ahead of elapsed-week pace. Banked resets suppress the weekly-pace rule. | Use low effort, batch small tasks into one brief, and handle trivial edits directly. Queue drain launches at most one low-effort worker. | [Setup · Usage self-management](../setup.md#usage-self-management), [Skill · Check budget first](../skills/codex/SKILL.md#1-check-budget-first-every-time), [Design · Contract D](codex-workers-design.md#contract-d-queue) |
| `STATUS=SQUEEZE` | In v0.2.7, the 5-hour window is in the 90% to 97% squeeze range and weekly usage is below 95%. | Drain at most one low-effort backlog worker at a time, with priority `-1` or lower. Save interactive and urgent work for another window. | [Skill · Check budget first](../skills/codex/SKILL.md#1-check-budget-first-every-time), [Design · v0.2.7 squeeze and fallback](codex-workers-design.md#v027-squeeze-and-fallback) |
| `STATUS=BLOCKED UNTIL=<epoch>` | Weekly usage is at least 95%, or the 5-hour window reached the blocking threshold. In v0.2.7 that threshold defaults to 97%, or 90% if Codex reports `rate_limit_reached_type`. | Handle small work directly. Queue the rest, tell the user the reset time, and drain after it. | [Setup · Usage self-management](../setup.md#usage-self-management), [Skill · Check budget first](../skills/codex/SKILL.md#1-check-budget-first-every-time), [Design · v0.2.7 squeeze and fallback](codex-workers-design.md#v027-squeeze-and-fallback) |
| `STATUS=UNKNOWN` | There is no usable usage snapshot for the budget verdict. | A direct run can proceed and produce a snapshot. Queue drain launches nothing under this status. | [Skill · Check budget first](../skills/codex/SKILL.md#1-check-budget-first-every-time), [Design · Contract D](codex-workers-design.md#contract-d-queue) |
| `ADVICE=REDEEM_RECOMMENDED` | The weekly window is blocked, or the 5-hour window is blocked and weekly usage is at least 50%. | If queued work cannot wait, ask the user to redeem a banked reset in Codex under **Settings → Usage → Redeem reset**. Only the user redeems. | [Skill · Banked resets](../skills/codex/SKILL.md#banked-resets) |
| `ADVICE=REDEEM_OPTIONAL` | The 5-hour window is blocked and weekly usage is low. | Wait for the 5-hour reset unless the work is urgent. For urgent work, offer the user the option to redeem. | [Skill · Banked resets](../skills/codex/SKILL.md#banked-resets) |
| `ADVICE=REDEEM_BEFORE_EXPIRY` | A banked reset expires within three days and a window is more than 20% used. | Remind the user once. On Plus, one redemption restores both windows. | [Skill · Banked resets](../skills/codex/SKILL.md#banked-resets) |
| The banked reset count still shows the old value after redemption | The count is cached, and refreshes for caches older than 10 minutes run in the background. | Run `scripts/codex-resets-refresh.sh` or wait 10 minutes for the count to update. | [Skill · Banked resets](../skills/codex/SKILL.md#banked-resets) |
| A launched queue entry failed with `rate_limit` | The worker hit a Codex rate limit. | Find the task with `codex-queue.sh failed`, run `codex-queue.sh requeue <id>`, and drain after the reset. For earlier completion, the same brief can go to a Claude subagent in the same workdir if the fallback budget permits it. | [Skill · Queue](../skills/codex/SKILL.md#queue-for-batches-and-for-blocked-budgets), [Design · v0.2.7 squeeze and fallback](codex-workers-design.md#v027-squeeze-and-fallback) |
| A launched queue entry failed with `error` | The run record classifies the failure as an error. | Find the task with `codex-queue.sh failed`, read the run log, then fix the brief or handle the work directly. | [Skill · Queue](../skills/codex/SKILL.md#queue-for-batches-and-for-blocked-budgets) |
| `claude-fallback-budget.sh reserve <label>` returns `BLOCKED` | The fallback budget gate denied the reservation. It uses a separate 10-point pool for Claude's 5-hour and weekly limits. | Skip the fallback and use the rate-limit requeue path. Settle every successful fallback reservation, even when the fallback run fails. | [Skill · Queue](../skills/codex/SKILL.md#queue-for-batches-and-for-blocked-budgets) |
